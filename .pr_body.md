## Why

vLLM's fused-MoE kernels rewrite the expert weights after loading: FlashInfer TRT-LLM converts `w13_weight`/`w2_weight` **in place** into its block layout (vllm-project/vllm#54699, shipped in 0.31, which #205 pulled in) and FlashInfer CUTLASS swaps the gate/up halves. molt's refit was a sequence of plain `model.load_weights()` flushes, so after the first broadcast the engines held checkpoint-layout bytes under a kernel that reads the processed layout. Shapes and names match, `--train.check_weight_update_equal` passes, training keeps running; only `vllm_kl`/pass@1 reveal it. vLLM 0.31 picks FlashInfer TRT-LLM for bf16 MoE on Blackwell by default, so every MoE recipe on B200/GB200/GB300 without batch invariance (which forces Triton) is affected.

## What

- `WorkerWrap.begin_weight_update` / `end_weight_update`: wrap the refit in vLLM's own layerwise reload (`initialize_layerwise_reload` before the first flush, `finalize_layerwise_reload` after the last). Each layer's loads are buffered and its `process_weights_after_loading` re-run once the layer is complete, with the result copied back into the storage the CUDA graphs captured. This is exactly what `GPUModelRunner.reload_weights(is_checkpoint_format=True)` does, split across molt's packed flushes so the broadcast protocol is unchanged. The flushes run under `set_current_vllm_config` because the deferred processing may read it.
- `TrainingActor.broadcast_to_vllm`: `pause → begin_weight_update → broadcast → end_weight_update → reset_prefix_cache → resume`.
- `--vllm.moe_backend` (vLLM `EngineArgs.moe_backend`), so a recipe can pin `triton`.
- Unit test for the worker bracket; README row for the flag.

Prior art: verl stages checkpoint-layout views and folds them back (verl-project/verl#7978); NeMo RL wraps TRT-LLM MoE modules in the same layerwise reload and offers `refit_with_reload_api`. This PR takes the vLLM-native route with no backend-specific code.

## Cost / behaviour change

Every refit now re-runs post-load processing for every layer (NeMo RL measured ~44% slower refit on Qwen3-30B-A3B via `reload_weights`). molt's broadcast is seconds against minutes-long steps. No opt-out flag on purpose; say so in review if you want one.
