Architecture

One loop.

Ray coordinates three kinds of processes: agent workers, vLLM rollout engines, and one trainer. In asynchronous mode the six stages overlap.

Rollout

vLLM engines

Generate tokens for the agents.

3Call tools and the model in turn, then return a reward.

Ray

Queue

Buffers finished trajectories and bounds policy lag.

Training

Trainer

NeMo AutoModel + FSDP2 update the policy.

6weight refit: new weights return to the engines
  • Black-box agents

    Train the agent you already have.

    Redirect an OpenAI or Anthropic client to Molt. When the agent rewrites its own context, the rollout is segmented automatically.

  • Fully asynchronous

    A slow episode delays only itself.

    Batches come from completed groups while other rollouts stay in flight. Stale samples are corrected with the log-probabilities recorded at sampling time.

  • Distributed experience

    Heavy data stays where it is produced.

    Screenshots and token sequences live in each node’s Ray object store. The queue carries only references.

NeMo AutoModel

Parallelism, applied from outside.

The policy stays an ordinary PyTorch module in the Hugging Face layout. FSDP2 shards its parameters, and three forms of parallelism divide the computation. Each is one flag.

Hugging Face-native

A new model needs no bridge.

The checkpoint loads directly, the rollout engines read the same directory, and the model code contains no parallel logic.

Bridged, the Megatron pathcode written for each model family
Hugging Face checkpoint→ Translate the configuration→ Convert weights to Megatron’s layout→ Megatron model→ Convert back at every weight refit→ Rollout engine
Native, the Molt path
Hugging Face checkpoint→ Ordinary PyTorch module in the Hugging Face layoutFSDP2 + TP / EP / CP wrap it from outside→ Rollout engine

Easy to modify

One path. Flat code. Small files.

One training backend, one rollout engine, and command-line flags as the only configuration. The function you edit is the function that runs.

Quick start

From clone to rollout.

A run is one command that names the checkpoint, the agent module, and the advantage estimator.

git clone https://github.com/NVIDIA-NeMo/labs-molt.git
cd labs-molt

# recommended: the prebuilt container with the whole CUDA 13 stack
docker pull hijkzzz/molt:latest
from openai import AsyncOpenAI
from molt.agents import ChatAgent, ChatAgentRunner, ChatContext, Result


class MyAgent(ChatAgent):
    async def run(self, ctx: ChatContext) -> Result:
        # ctx.base_url carries the session id and auto-captures the token
        # trace — no extra_body, no logprobs=True, no session plumbing.
        client = AsyncOpenAI(base_url=ctx.base_url, api_key=ctx.api_key)
        resp = await client.chat.completions.create(
            model=ctx.model_name,
            messages=[{"role": "user", "content": ctx.prompt}],
            max_tokens=ctx.sampling_params.max_tokens,
            temperature=ctx.sampling_params.temperature,
        )
        return Result(reward=grade(resp.choices[0].message.content, ctx.label))


class AgentRunner(ChatAgentRunner):
    def __init__(self):
        super().__init__(MyAgent)
python3 -m molt.cli.train_rl_ray \
  --actor.model_name_or_path /path/to/automodel \
  --data.prompt_dataset /path/to/prompts.jsonl \
  --data.input_key input \
  --data.label_key answer \
  --train.agent_path examples/python/agents/math.py \
  --vllm.num_engines 2 \
  --vllm.tensor_parallel_size 2 \
  --rollout.batch_size 128 \
  --train.batch_size 128 \
  --train.micro_batch_size 1 \
  --algo.advantage.estimator reinforce \
  --fsdp.attn_implementation te \
  --ckpt.output_dir ./ckpt/rl
torchrun --standalone --nproc_per_node=8 -m molt.cli.train_sft \
  --model.model_name_or_path /path/to/automodel \
  --data.dataset /path/to/sft.jsonl \
  --data.input_key input \
  --data.output_key output \
  --ckpt.output_dir ./ckpt/sft \
  --fsdp.attn_implementation te
